# Avito services hackathon

Помощник для определения дополнительных ремонтных услуг в объявлении и подготовки фактических черновиков.

## Текущий этап

Техническая подготовка этапа 1 выполнена. Программная часть первого прототипа реализована и независимо проверена: baseline обучен, локальный LLM-клиент/интерфейс и инструменты экспериментов готовы. Реальная модель на GPU ещё не запущена; её качество не измерено. Актуальный статус — [отчёт](docs/STATUS.md); запуск — [инструкция](docs/LOCAL_RUN.md); [команды синтетики и сравнения](docs/EXPERIMENTS.md). Исторический PDF описывает постановку и архитектурный план, а не текущие результаты экспериментов.

## Что выяснили

- Train: 10 000 строк, 4 855 уникальных описаний после нормализации регистра/пробелов. Метки автоматические, потенциально ошибочные.
- Public-test: 208 строк; 24 пересекаются с train после нормализации. Исходного `mcId` нет. Назначение набора требует уточнения.
- Подготовлены 50 development и 50 control, все `provisional`. Из обучения baseline исключаются все их группы: 363 строки; остаётся 9 637.
- Подготовлены 17 синтетических проверок; два пакетных случая ожидают решения организаторов.

## Локальное воспроизведение

Нужны Python 3.12 и исходный ZIP, который в Git не включён. Из корня проекта в PowerShell:

```powershell
python -m pip install --target .tools/python --no-cache-dir --no-deps -r requirements-stage1.txt
python scripts/audit_data.py --archive 'C:/Users/Admin/Downloads/innoglobalhack_avito(1).zip'
python scripts/prepare_review.py --archive 'C:/Users/Admin/Downloads/innoglobalhack_avito(1).zip'
python scripts/prepare_review.py --archive 'C:/Users/Admin/Downloads/innoglobalhack_avito(1).zip' --verify
```

При первом запуске выборки создаются; повторный запуск проверяет их и отказывается перезаписывать отличающиеся файлы. Для обучения использовать `training_exclusions_manifest.jsonl`: прежний флаг `excluded_from_training` в исходном манифесте учитывал только control.

Исходный датасет, локальные выборки, манифесты, зависимости и временные материалы не публикуются. Подготовку можно воспроизвести из ZIP; human-review хранится отдельно от замороженных исходных примеров.

## Дальше

Команде проверить 100 примеров и разобрать спорные метки; получить ответы менторов на вопросы последней страницы PDF. Разметку можно вести параллельно прототипу. Для удобства открыть локальную [форму разметки](tools/review.html): она не отправляет данные в сеть и скачивает отдельный human-review файл. Платные API не вызывались.

## Структура проекта

Baseline — простой обученный классификатор для сравнения с LLM. Development — рабочие примеры для выбора и исправления решения. Control — отдельные контрольные примеры для финальной оценки; по ним решение не настраиваем. Provisional означает, что метка ещё не подтверждена человеком.

| Папка / файл | Назначение |
|---|---|
| `avito/` | Код решения: загрузка данных, baseline, LLM-клиент, HTTP-интерфейс и CLI. |
| `scripts/` | Команды аудита, подготовки выборок, обучения и установки/старта локальной модели. |
| `tests/` | Проверки контракта, изоляции данных, ошибок и безопасной подготовки runtime. |
| `tools/review.html` | Локальная форма ручной разметки. |
| `notebooks/` | Notebook для приватного запуска с GPU в Colab/Kaggle. |
| `docs/stage1/` | Аудит и протокол; там же приватные review/manifests, которые Git игнорирует. |
| `docs/superpowers/plans/` | Согласованные планы; текущий — `2026-11-14-prototype.md`. |
| `output/pdf/` | Отчёт по постановке и архитектуре с вопросами ментору. |
| `data/` | Приватные веса, обученные модели, подробные предсказания и результаты опытов; целиком вне Git. |
| `.tools/` | Локальные Python-зависимости и portable runtime; вне Git. |
| `tmp/`, `.superpowers/` | Сохранённые тестовые материалы, рендеры и журналы агентов; вне Git, автоматически не удаляются. |
| `AGENTS.md`, `requirements-*.txt` | Правила работы агента и закреплённые зависимости. |

Git содержит код, тесты и документы. Реальные объявления, контрольные тексты, модельные веса и окружение остаются приватными. Путь нового объявления: ввод в интерфейсе → один запрос локальной модели → проверка JSON и оснований → категории и черновики рядом с исходником. Правильность смысла и обещаний требует отдельной проверки.
