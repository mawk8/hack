# Локальный запуск: модель → backend → браузер

Инструкция для Windows 10/11 x64 и PowerShell. Все команды выполняются **из корня проекта**. Для демо нужны два открытых терминала: в первом работает модель, во втором — Python backend. Интерфейс открывается в браузере.

**Что уже проверено:** установка закреплённых Python-зависимостей на Windows/Python 3.12, `pip check`, тесты приложения и синтетические HTTP-ответы. **Что ещё не подтверждено:** скачивание и совместимость выбранного llama.cpp runtime, реальная генерация, скорость и фактичность на GPU. RTX 3060 12 GB у товарища пока недоступна; доступный агенту ноутбук имеет RTX 3050 Laptop 4 GB. Ранее скачивание runtime в этой сессии было отклонено и не повторялось. Команды ниже предназначены для самостоятельного запуска на выбранном ПК; наличие команды в инструкции не означает, что скачивание уже выполнено или разрешено агенту здесь.

## 1. Подготовить компьютер и получить проект

Нужны Git, **Python 3.12 x64**, интернет для Python-пакетов и отдельного скачивания модели/runtime. Для GPU-сборки нужен NVIDIA GPU и совместимый драйвер. Проверить установленный GPU можно командой `nvidia-smi`; наличие устройства ещё не доказывает совместимость runtime. Веса модели занимают около 5 GB; дополнительно нужны место для runtime, его архивов и Python-окружения. Не рассчитывайте только на 5 GB свободного места.

Откройте PowerShell. Для новой копии, если папки `E:\hackaton` ещё нет:

```powershell
Set-Location E:\
git clone https://github.com/mawk8/hack.git hackaton
Set-Location E:\hackaton
git switch prototype
git pull --ff-only origin prototype
```

Если репозиторий уже есть, **не клонируйте поверх него**:

```powershell
Set-Location E:\hackaton
git status --short --branch
```

Если есть локальные изменения, сначала разберите их с владельцем: не выполняйте reset/clean и не перезаписывайте файлы. Для чистой рабочей копии:

```powershell
git switch prototype
git pull --ff-only origin prototype
```

Далее предполагается путь `E:\hackaton`. Если вы выбрали другой, заменяйте его в `Set-Location`. Не копируйте чужие `.venv`, `.tools` и `llama-runtime.json`: окружение и пути создаются на новом компьютере.

## 2. Создать Python-окружение один раз

```powershell
py -3.12 -VV
py -3.12 -c "import struct; print('bits:', struct.calcsize('P') * 8)"
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements-prototype.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -VV
```

Ожидаются Python 3.12, `bits: 64` и `No broken requirements found.`. Если `.venv` уже существует, не пересоздавайте её вслепую: проверьте версию последней командой. Активация окружения не нужна; во всех командах явно используется его Python. Это также исключает случайный запуск через Anaconda или другой `python` из PATH.

Если `py -3.12` не найден, установите Python 3.12 x64 либо используйте полный путь к уже установленному интерпретатору, например `& 'C:\путь\Python312\python.exe' -m venv .venv`. Не меняйте глобальные настройки Python ради этого проекта.

Проверка кода без модели:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют синтетические ответы. Их успешность не означает, что LLM установлена или выдаёт правильные категории.

## 3. Скачать модель и runtime один раз

Этот шаг требует осознанной готовности скачать **около 5 GB модели плюс runtime**. Из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts/setup_local_llm.py --install
```

Дождитесь завершения команды без ошибки. Установщик создаёт:

- `data/models/Qwen3-8B-Q4_K_M.gguf` — официальный Qwen3-8B Q4_K_M, 5 027 783 488 байт;
- `.tools/llama-downloads/` — скачанные архивы;
- `.tools/llama-…-cuda-…/` — переносимый llama.cpp CUDA12;
- `.tools/llama-runtime.json` — пути именно этого компьютера и параметры запуска.

Модель закреплена ревизией и SHA256. Указатель runtime также проверяется по закреплённому SHA256, архивы — по опубликованным хэшам. При отсутствии подходящей CUDA12-сборки/хэша установка останавливается. Существующие файлы проверяются; повреждённый или незавершённый файл **сохраняется и не используется**. Установщик не перезаписывает и не удаляет его автоматически.

Без скачивания можно проверить только наличие manifest:

```powershell
.\.venv\Scripts\python.exe scripts/setup_local_llm.py
```

`installed: true` здесь означает наличие manifest, а не успешный запуск модели.

## 4. Терминал №1 — запустить сервер модели

В том же PowerShell после установки:

```powershell
Set-Location E:\hackaton
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_local_llm.ps1
```

`ExecutionPolicy Bypass` относится к этому дочернему процессу PowerShell; глобальная политика не меняется. Сервер работает в текущем окне, выводит сообщения и занимает терминал — это нормально. Оставьте окно открытым. Не запускайте второй экземпляр на том же порту.

Стандартные настройки: `127.0.0.1:8080`, alias `avito-qwen3-8b`, контекст 8192, один одновременный запрос, `GpuLayers=99`. Возможность полного размещения на конкретной GPU надо проверить запуском.

## 5. Терминал №2 — проверить модель, затем запустить backend

Откройте **второй PowerShell**. Первый с моделью продолжает работать:

```powershell
Set-Location E:\hackaton
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/health'
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/v1/models' | ConvertTo-Json -Depth 5
```

Продолжайте после успешного HTTP-ответа `/health` и появления `avito-qwen3-8b` в списке моделей. Пока веса загружаются, проверка может отвечать ошибкой: смотрите терминал №1 и повторите после загрузки. Один только список моделей не проверяет генерацию.

Теперь запустите приложение:

```powershell
.\.venv\Scripts\python.exe -m avito serve
```

Ожидается строка `Демо: http://127.0.0.1:7860 (модель: http://127.0.0.1:8080/v1)`. Терминал №2 тоже остаётся занят сервером.

**Frontend уже входит в backend:** это `avito/ui.html`, который Python отдаёт по адресу `/`. Node.js, npm, отдельная сборка и третий сервер не нужны. Данные хакатона, обучение baseline и исходный ZIP для демо не нужны.

## 6. Открыть страницу и проверить полный сценарий

В браузере вручную откройте [http://127.0.0.1:7860](http://127.0.0.1:7860). Браузер не является третьим терминалом. Оба PowerShell должны оставаться открыты.

1. Вставьте **синтетический** текст, например: `Выполняю ремонт квартир. Укладываю плитку в ванной. Плиточные работы принимаю и отдельным заказом.` Исходная категория уже фиксирована: 101.
2. Нажмите **«Найти услуги»**. Модель возвращает категории 102–106, цитаты из исходника и ограничения. Все галочки изначально сняты. Ожидаемая услуга в этом примере — плиточные работы (103); реальное поведение модели ещё предстоит проверить.
3. Проверьте цитаты и смысл услуги, отметьте интересующие категории. Пока ничего не выбрано, генерация недоступна.
4. Нажмите **«Создать черновики для выбранных»**. Будут созданы только выбранные черновики. Проверьте, что модель не добавила цены, гарантии, услуги или возможность отдельного заказа без основания в исходнике.
5. Нажмите **«Скачать JSON результатов»** для сохранения диагностического результата. Он содержит исходник, весь автоматический список, пользовательский выбор, черновики, статусы и ошибки.

Редактирование исходного текста сбрасывает найденные категории, выбор и черновики: поиск нужно выполнить заново. Изменение галочек сбрасывает прежние черновики соответствующей записи. Автоматически найденный список сохраняется отдельно от выбора.

Настоящий пустой результат допустим. Сбой сервера, тайм-аут или неверный ответ модели показываются как ошибка; их нельзя считать успешным результатом «услуг нет». Для F1 нужен **полный автоматический список до галочек** (`automatic_categories`), а не только выбранные пользователем категории.

## 7. Табличный режим CSV

Сохраните небольшой CSV в **UTF-8** (допустим UTF-8 с BOM). Разделитель — запятая, точка с запятой либо табуляция. Минимальный пример с официальным идентификатором:

```csv
testcase,description
case-001,"Выполняю ремонт квартир. Укладываю плитку в ванной. Плиточные работы принимаю отдельно."
case-002,"Ищу электрика для своей квартиры. Услуги сам не оказываю."
```

`description` — обязательный текст объявления и единственный текстовый вход модели. `testcase` — идентификатор официального формата; поддерживается также `id`. Не указывайте `id` и `testcase` одновременно. `title` — необязательное отображаемое название, оно не добавляется к тексту для модели. Без идентификатора используются номера записей, начиная с `1`. Пустые и повторяющиеся идентификаторы отклоняются. Лимиты: 200 записей, 2 MiB, до 12000 символов в каждом `description`.

В интерфейсе выберите CSV, нажмите **«Импортировать и найти услуги»**. Строки проходят обнаружение последовательно, виден прогресс. Затем отметьте категории отдельно у каждой записи и запустите генерацию. Ошибка одной записи отображается отдельно и сохраняется в экспорте; она не превращается в пустой правильный ответ.

Для диагностического JSON используйте **«Скачать JSON результатов»**. Для обмена в формате задания нажмите **«Скачать CSV для сдачи»**. Кнопка доступна, когда поиск успешен у всех записей и черновики созданы для **всех автоматически найденных категорий** каждой непустой записи. Если выбран только поднабор, есть ошибка или генерация не закончена, сдача блокируется; диагностический JSON остаётся доступен. При пустом успешном обнаружении ответ содержит `[],[]`, генерация не нужна. Колонки ответа:

```csv
testcase,microcats,descriptions
```

В ячейках `microcats` и `descriptions` находятся **JSON-массивы**, а не строки с перечислением через запятую. При чтении CSV сначала разбирайте таблицу CSV-парсером, затем каждую такую ячейку JSON-парсером. Не делите строку простым `split(',')`: кавычки и запятые внутри массивов являются частью формата. `testcase` связывает ответ с исходной записью. Массив `microcats` содержит весь автоматический набор, а `descriptions` — тексты черновиков в том же порядке. Для оценки F1 также используйте весь `automatic_categories` полного JSON; пользовательский поднабор не подменяет прогноз модели. Порядок/правила официальной отправки и private-submit нужно подтвердить у организаторов; локальный экспорт сам ничего не отправляет.

## 8. Если не запускается

| Симптом | Что проверить и сделать |
|---|---|
| `py` или Python 3.12 не найден | Проверьте установленный Python 3.12 x64. При наличии используйте полный путь к нему для создания venv. |
| Ошибка import / запускается Anaconda | Используйте именно `.\.venv\Scripts\python.exe`. Проверьте `-VV`, `-m pip check`; установите зависимости из `requirements-prototype.txt` этим же интерпретатором. |
| `Checksum mismatch` / manifest отличается | Установщик сохранил проблемный файл и остановился. Сверьте путь из сообщения, источник и хэш. Не отключайте проверку и не удаляйте файлы автоматически; исправление конкретного файла согласуйте с владельцем. Повторный запуск не исправляет незавершённое скачивание сам. |
| Нет manifest / runtime executable / model file | Установка не завершена либо перенесён чужой manifest. Вернитесь к шагу 3 и диагностируйте сообщение установщика. |
| DLL/CUDA error, модель не стартует | Смотрите полный вывод терминала №1 и `nvidia-smi`. Совместимость скачанной сборки ещё не подтверждена; не скачивайте случайные DLL и не меняйте драйверы вслепую. |
| Не хватает VRAM | Остановите свой сервер модели `Ctrl+C` и попробуйте `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_local_llm.ps1 -Context 4096 -GpuLayers 20`. Это другая конфигурация; фиксируйте её отдельно. |
| Нет подходящей GPU | Можно попробовать существующий флаг `-GpuLayers 0` с `-Context 4096`. CPU/offload зависит от работоспособности выбранного CUDA-runtime; CPU-режим на этом runtime не подтверждён и может оказаться слишком медленным для тайм-аута приложения. |
| `503 model_unavailable` | Backend доступен, но LLM недоступна. Проверьте терминал №1, `/health` на 8080, `/v1/models` и endpoint backend. |
| `503 busy` | Модель уже выполняет запрос. Дождитесь завершения; не запускайте параллельно CLI, вторую вкладку или второй пакет. |
| Тайм-аут / неверный ответ | Это техническая ошибка, а не отсутствие категорий. Сохраните код ошибки и время, проверьте сервер модели; успешный `/health` не доказывает успешность генерации. |
| Порт занят / страница не открывается | Убедитесь, что не запущен второй экземпляр. Для проверки портов используйте команды ниже. Не останавливайте чужой процесс вслепую. |
| CSV не импортируется | Проверьте UTF-8, точные имена колонок, уникальные ID, лимиты и CSV-кавычки. Формат `.xlsx` напрямую не поддерживается. |

Если нужны другие порты, сначала остановите **свои** серверы `Ctrl+C`, затем запустите согласованно. Терминал №1:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_local_llm.ps1 -Port 8081
```

Терминал №2:

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8081/health'
Invoke-RestMethod -Uri 'http://127.0.0.1:8081/v1/models'
.\.venv\Scripts\python.exe -m avito serve --port 7861 --endpoint http://127.0.0.1:8081/v1 --model avito-qwen3-8b
```

Открывайте тогда [http://127.0.0.1:7861](http://127.0.0.1:7861). Суффикс `/v1` в `--endpoint` обязателен. Стандартные порты можно проверить до запуска backend, в свободном терминале:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8080,7860 -ErrorAction SilentlyContinue |
    Select-Object LocalAddress,LocalPort,OwningProcess
Invoke-RestMethod -Uri 'http://127.0.0.1:7860/health'
```

Последняя команда относится **к backend**, возвращает `status: ok, model_status: not_checked` и не проверяет доступность LLM. Для завершения демо нажмите `Ctrl+C` в каждом из двух окон. Файлы, веса и кэши остаются на месте для следующего запуска.

Для диагностики передавайте команду, полный traceback, вывод `-VV` / `-m pip check`, GPU, версию runtime и код ошибки. Не присылайте ключи, реальные объявления и контрольные ответы. После реального запуска зафиксируйте конфигурацию, detection/generation и полное время с ошибками/повторами на синтетическом примере. Это и будет проверка GPU; тестовый HTTP-ответ её не заменяет.

## 9. Только при необходимости: baseline и данные

Для демо этот раздел пропускается. Исходный ZIP, frozen-файлы и веса не входят в Git. Для нового checkout только с исходным ZIP сначала восстановите v1, затем создайте v2; существующие файлы не перезаписываются:

.\.venv\Scripts\python.exe scripts/prepare_review.py --archive $ExperimentArchive
.\.venv\Scripts\python.exe scripts/prepare_data_v2.py --archive $ExperimentArchive

Для текущей v2 ожидаются 8944 train-строки и 208 public development. Если приватная `data/v2/` уже получена, не пересоздавайте её; нужен тот же ZIP. `--output-dir` всегда новый. На чистой копии кода проверена последовательность `prepare_review.py` → `prepare_data_v2.py`: 13 файлов v2 совпали по SHA256. Метки шумные. ## 10. Облачный вариант — отдельный, пока не проверен

Подготовлен `notebooks/avito_gpu.ipynb`; локальному демо он не нужен. В Colab/Kaggle выбирается GPU и приватная сессия с интернетом; доступ/квоты зависят от сервиса и аккаунта. Запуск notebook в облаке не проверен.

`python scripts/package_notebook.py` создаёт ZIP исходников и requirements. Source-bundle и исходный ZIP данных добавляются в приватную сессию отдельно, пути задаются в notebook. Не вставляйте GitHub-токен в ячейки и не публикуйте данные, предсказания, веса или секреты. Notebook не поднимает публичный веб-сервис. Для реального демо предпочтителен проверенный стабильный ПК; публичный туннель не требуется.

Источники загрузок, используемые установщиком: [официальный Qwen GGUF](https://huggingface.co/Qwen/Qwen3-8B-GGUF), [официальный llama.cpp](https://github.com/ggml-org/llama.cpp). Подробные факты о проверках проекта — [STATUS.md](STATUS.md).
