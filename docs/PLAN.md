# Актуальный план MVP

Обновлено 15.11.2026: приоритеты пересмотрены после разбора условий (`task/`) и методологии. Этот документ заменяет прежние планы для дальнейшей работы. Код: ветка `prototype`.

## Цель и ограничения

- Входные объявления всегда из 101; предсказываем 102–106. В интерфейсе source фиксирован, совместимость API сохраняем.
- Оценка 5/3/2: классификация, работоспособность, черновики. В `task/hackathon-evaluation.md` указано 60/25/15 — сверить с PDF критериев; порядок приоритетов от этого не меняется. Черновики не публикуются автоматически.
- Срок по записи ментора: 16 ноября 08:00; точное время/часовой пояс и правила private-submit подтвердить в чате организаторов.
- Качество важнее скорости. Только открытые локальные модели, платные API не используем. Железо: сейчас доступна 2080 Super 8 ГБ, целевая — 3060 12 ГБ, RAM 32 ГБ.
- Public разрешён для настройки, его метки шумные. Кандидата выбираем групповой CV на public (см. «Оценка»).
- Приоритет — полный MVP на реальной LLM. Массовую синтетику и дообучение LLM отложить; существующие инструменты сохранить.

## Оценка

- Public: 139 уникальных описаний. Конфликтные группы (13) сводить большинством, при равенстве исключать. Все выборы (статусы, пороги, веса стекинга) — групповая CV и bootstrap.
- Разброс F1 на 139 текстах порядка ±0.04–0.05 (оценка, не измерение). Меньшую разницу улучшением не считать, брать более простой вариант.
- Модельные метки — silver, не человеческий эталон. Не выставлять human_verified вместо человека.
- Час ручной работы — на разбор расхождений модели с public, прежде всего ложных срабатываний, а не на слепую разметку 40.

## Эксперименты

| Опыт | Меняем только | Фиксируем |
|---|---|---|
| E1 — признаки | Символы → символы+слова TF-IDF | Данные, LR, очистка, порог |
| E3 — порог | Глобальный порог против порогов по категориям | Модель; выбор только по CV |
| E4 — динамический few-shot | k ближайших по эмбеддингу размеченных примеров вместо фиксированных 6–10 | Qwen, справочник, настройки генерации; та же группа исключается |
| E5 — каскад | LLM решает только серую зону классификатора; logprob «да/нет» — признак в LR поверх TF-IDF | Классификатор, границы зоны; полный исходник доступен LLM |
| E6 — метки | 5–10 % подозрительных train-меток (out-of-fold) переразмечены LLM как silver | Те же тексты/группы и классификатор |
| E7 — статусы | Ответ LLM: цитата + статус (отдельно / только этап ремонта под ключ / отрицание / чужая услуга / материалы) вместо да/нет | Модель, справочник; положительные статусы выбираются на public |
| E8 — эмбеддинги | Эмбеддинги + LR в стекинге с TF-IDF; при времени — дообучение энкодера на train | Данные, разбиение, порог |
| E9 — минимальные пары | 60–100 пар с заменой одной фразы (предлагаем / не делаем / делает чужой мастер) как стресс-набор и hard negatives | Модель; метка известна по построению |
| E2 — отложен | Нормализация омоглифов для ML | — |

Приоритет: реальный Qwen → E7 → E5 → E4 → E8. E1/E3 — дешёвые дополнительные проверки; E6/E9 — по остатку времени. Thinking включать для классификации, выключать для генерации — проверить отдельным замером.

От товарища берём идеи словесных признаков, нормализации, анализа ошибок и гибрида. Не переносим агрессивное отрезание SEO-хвоста, проверяющий с одобрением при сбое, произвольный fallback-текст или некалиброванные веса 50/50 как готовое решение. Полные замеры включают генерацию/сбои/повторы; кэшированные ответы не считать онлайн-скоростью.

## Черновики и отказоустойчивость

- Сначала отбор фрагментов исходника по категории и общих условий (район, график, опыт, оплата), затем LLM переписывает только их, сохраняя лицо (я/мы) и манеру автора.
- Детерминированный контролёр: числа, цены, сроки и слова «гарантия», «договор», «скидка», «бесплатно», «отдельно» в черновике должны быть в исходнике; ссылки на исходное объявление запрещены. Нарушение — одна перегенерация, затем явная ошибка.
- LLM-проверяющий — второй слой только для смысла (субъект услуги, ограничения) и только по конкретным ошибкам.
- LLM недоступна: вернуть категории классификатора с `title/text = null` и явным флагом деградации, не `drafts: []`.
- На защите показать разобранные уязвимости: инъекция в тексте объявления, белый список `mcId`, пустые и очень длинные тексты; слайд со временем по стадиям, токенами и стоимостью 0 ₽.

## Сабмиты

Попыток 2–3, эталон не выдаётся. Порядок фиксируем заранее:

1. Лучший кандидат по CV на public.
2. Тот же с одним переключённым правилом (строже к «пакетным» услугам): разница на лидерборде показывает политику private.
3. Победитель из двух.

## Как работать с планом

1. Взять ближайшую незавершённую задачу. Прочитать только связанный код и STATUS.md.
2. Перед опытом записать гипотезу, версии данных/модели/промпта и изменяемую переменную.
3. Выполнить небольшую законченную часть; проверить сценарий и существенные ошибки. Использовать Ponytail для простоты, Superpowers для исполнения/review по необходимости.
4. Получить независимую проверку существенного изменения; исправить подтверждённые замечания.
5. В STATUS.md записать результат, команду/артефакт и ограничение; обновить статус строки здесь, сделать scoped commit и push в prototype.
6. При изменении требований обновить этот план, а не создавать очередную параллельную версию.

## Внешние зависимости

- GPU: 3060 товарища ещё не настроена, доступна 2080 Super 8 ГБ. Реального LLM-прогона нет.
- Замена модели (Qwen3-14B Q4_K_M на 12 ГБ; русскоязычные T-lite/T-pro, YandexGPT-5-Lite-8B для генерации) требует скачивания, которое ранее было отклонено. Нужно решение пользователя; актуальные версии моделей проверить.
- API и баланса нет, платные вызовы не планируются.
- Пакетные/партнёрские услуги, точный deadline, веса критериев и формат/число submit остаются вопросами организаторам.
