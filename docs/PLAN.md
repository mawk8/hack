Модельные метки — silver, не человеческий эталон. Учителя/правила фиксируем на development до разметки контроля. Человеческие 40 — без исходных меток и подсказок, закрыты до выбора кандидата. Неразрешённые случаи отмечать явно; CI на silver измеряет согласие с учителем, не истинную точность. На 40 не обещаем достоверность малых улучшений.

## Эксперименты

| Опыт | Меняем только | Фиксируем |
|---|---|---|
| E1 — признаки |Символы → символы+слова TF-IDF |Данные, LR, очистка, порог |
| E2 — смешанная раскладка |Осторожную нормализацию омоглифов для ML |Оригинал/evidence, разбиение, модель |
| E3 — порог |Глобальный порог из 0.3/0.4/0.5/0.6/0.7 |Модель и development; результат не независимыйtest |
| E4 — few-shot |Добавление 6–10development-примеров |Qwen, справочник, настройки генерации |
| E5 — гибрид |Подсказки TF-IDF для Qwen |Qwen может отвергнуть/добавить категории; полный исходник доступен |
| E6 — метки, после MVP |Часть перепроверенных training-меток |Те же тексты/группы и классификатор; контроль не брать в обучение |

Приоритет:E1 → реальный Qwen → E4 → E5. E2/E3 — дешёвые дополнительные проверки, E6 — при наличии времени. Отдельные классификация/генерация и LLM-проверяющий — только по конкретным ошибкам, не автоматическое усложнение.

От товарища берём идеи словесных признаков, нормализации, анализа ошибок и гибрида. Не переносим агрессивное отрезание SEO-хвоста, проверяющий с одобрением при сбое, произвольный fallback-текст или некалиброванные веса 50/50 как готовое решение. Полные замеры включают генерацию/сбои/повторы; кэшированные ответы не считать онлайн-скоростью.

## Как работать с планом

1. Взять ближайшую незавершённую задачу. Прочитать только связанный код и STATUS.md.
2. Перед опытом записать гипотезу, версии данных/модели/промпта и изменяемую переменную.
3. Выполнить небольшую законченную часть; проверить сценарий и существенные ошибки. Использовать Ponytail для простоты, Superpowers для исполнения/review по необходимости.
4. Получить независимую проверку существенного изменения; исправить подтверждённые замечания.
5. В STATUS.md записать результат, команду/артефакт и ограничение; обновить статус строки здесь, сделать scoped commit и push в prototype.
6. При изменении требований обновить этот план, а не создавать очередную параллельную версию.
