# Данные v2: как работать

Подготовка выполняется локально, исходный ZIP и прежние файлы не изменяются. Использовать Python 3.12 из venv по [LOCAL_RUN.md](LOCAL_RUN.md). На новом checkout frozen v1 не входят в Git: сначала восстановить их из того же ZIP, затем создать v2:

```powershell
.\.venv\Scripts\python.exe scripts/prepare_review.py --archive 'ПУТЬ/innoglobalhack_avito(1).zip'
.\.venv\Scripts\python.exe scripts/prepare_data_v2.py --archive 'ПУТЬ/innoglobalhack_avito(1).zip'
.\.venv\Scripts\python.exe scripts/prepare_data_v2.py --archive 'ПУТЬ/innoglobalhack_avito(1).zip' --verify
```

Результат — приватная папка `data/v2/`, целиком вне Git. Создание не перезаписывает существующие файлы; повторный запуск проверяет воспроизводимость. На чистой копии исходников с тем же ZIP заново получены v1 и v2: все 13 файлов v2, включая манифест, совпали по SHA256 с текущими. Закрытые файлы при сравнении проверялись как непрозрачные байты. Новое разбиение не означает, что метки уже исправлены.

Фактическая версия от 15.11: 8944 train-строки; 208 исходных public / 139 уникальных описаний; 200 контрольных групп и 40 слепых примеров. Исключено 1056 исходных train-строк. Новые контрольные группы выбраны равновероятно из 4137 допустимых групп без использования меток.

В `summary.json` величина `excluded_groups=314` относится к группам с train-строками, а `excluded_groups_by_reason.public=129` включает также public-группы без train. Причины исключения пересекаются, их количества не складываются. Непосредственная проверка отсутствия пересечений важнее суммы этих счётчиков.

| Файл | Кому и зачем |
|---|---|
| `train.jsonl` | Разрешённые исходные строки для обучения, после исключения целых групп |
| `development_original.jsonl` | 208 public-строк с исходными шумными метками; только рабочая оценка |
| `development_review.jsonl` | Уникальные public-описания и все варианты исходных меток; конфликт не решается автоматически |
| `development_teacher_input.jsonl` | Входы для будущей переразметки без старых ответов |
| `control_reference.jsonl` | 200 закрытых примеров с исходными шумными метками; только ответственному оценщику |
| `control_teacher_input.jsonl` | Закрытые входы для фиксированного учителя; не передавать агенту настройки |
| `human40_blind_review.jsonl` | Случайные 40 примеров для слепой проверки человеком, без старых меток |
| `manifest.json`, прочие манифесты | Контрольные суммы, группы, происхождение и причины исключения |

## Твои 40 примеров

1. Открыть локально `tools/review.html`, выбрать `data/v2/human40_blind_review.jsonl`, указать имя.
2. Прочитать текст и отметить только реально предлагаемые услуги. Никаких подсказок модели или старых ответов.
3. Для выбранных категорий вписать точные цитаты. Отрицания, прошлый опыт, чужие услуги и поиск работника не равны предложению услуги.
4. Не переносить цену/гарантию/срок на другую услугу без основания. Неясные пакеты и партнёрские работы помечать «Спорный случай» с пояснением, а не угадывать.
5. Подтвердить проверку и нажать «Сохранить решение» **до перехода к следующему примеру**. Отрицательный ответ тоже требует внимательного прочтения.
6. Регулярно скачивать отдельный human-review файл в `data/reviews/`. Исходный blind-файл не перезаписывать. При продолжении открывать сохранённый экспорт, не начинать заново.

Ответы и сомнения по этим 40 остаются у оценщика до фиксации кандидата. Для обсуждения правил сначала используем public-примеры, а не ошибки контроля. `human_verified` выставляет только человек; незавершённое остаётся `provisional`, спорное — `disputed`.

## Обучение и оценка

Когда `data/v2/` подготовлена, общий загрузчик автоматически использует её. Неполная или повреждённая v2 вызывает ошибку, а не откат к v1. Можно явно указать `--data-dir data/v2` в командах обучения и сравнения. Размеры берутся из новой версии, не из прежних чисел 9637/50.

Старый baseline не пригоден для нового контроля: он мог обучаться на его группах. Переобучение и E1 выполнены: char F1=0.7670, char+word=0.7601 на тех же 208 noisy public-строках; выигрыша от слов пока нет. Версии, хэши и ограничения — в [STATUS.md](STATUS.md).

Исходные public/train-метки остаются шумными; массовая переразметка не проведена, есть только пилот ниже. Автоматическая переразметка — silver, не human gold. Контроль выбирается равновероятно среди оставшихся независимых групп: это оценка на уникальных группах, не гарантированно распределение официального private. Полного отсутствия перефразированных дублей эвристика не доказывает.

## Разрешённый пилот Codex: 20 public-примеров

Приватные файлы: `data/annotations/public-pilot20/inputs.jsonl`, `teacher.jsonl`, `validation_summary.json`. Выбор детерминированный среди уникальных public, без старых ответов на входе. GPT-6 Astra разметила все 20 примеров по пяти категориям с точными цитатами и статусом `silver_provisional`.

Проверены структура, идентификаторы, хэши исходников и присутствие всех цитат. В 18 примерах метки совпали хотя бы с одним исходным вариантом, в двух предложены изменения. В одном из этих 20 примеров две категории остаются неопределёнными из-за неуказанного типа тёплого пола. Это сравнение разметок, не точность модели. Выборочная смысловая проверка public-разногласий проведена ассистентом, не человеком; человеческих gold-меток этим не создано.

Пилот использовал текущий Codex, его расход лимитов отдельно не измерен; платный API не вызывался. Остальные public и контрольные 200 не переразмечены. Не расширять пилот автоматически и не подменять им human40. Метки пилота не записываются поверх исходных/frozen-файлов и пока не подмешиваются в обучение.
