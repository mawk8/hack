# Главная выжимка защиты · defense.pdf, 14 слайдов

- **Проблема:** упомянутая работа не всегда предлагается. Нужно учитывать отрицания, чужих исполнителей и ограничения заказа.
- **Решение:** словарь + TF-IDF находят кандидатов → одна локальная LLM проверяет смысл в разных ролях → отдельно создаётся черновик.
- **Зачем panel:** мягкий судья защищает от пропусков, строгий ищет причины исключения, арбитр разбирает спор. Больше проверок означает больше времени; универсальный выигрыш не доказан.
- **Тексты:** не дописываем услуги, цены и гарантии. Промпты задают краткость, «я/мы» и отсутствие воды; код проверяет нарушения, возможны исправление и шаблон. Проверка человеком остаётся нужна.
- **Три эксперимента:** весь текст приводил к пропускам → выделили строки; один строгий судья терял услуги → добавили мягкого и арбитра; замечания при повторе помогали исправлять черновики → оставили одну попытку исправления.
- **Что нового в PDF:** для50 объявлений приведены11,3с с LLM-черновиками и4,3с с шаблонными; в LLM-режиме28,2% черновиков перешли на шаблон. Это разные режимы текста, судьи в обоих используют LLM. Эталона нет — нового F1 нет.
- **Что показали прежние опыты:** на собственном сложном наборе panel уменьшала лишние категории; на публичном срезе выигрыша не было. Это основание для выбора архитектуры, а не обещание качества на любых данных.

**Одна фраза на память:** «Сначала находим возможную услугу, затем проверяем, действительно ли её предлагают, и только потом готовим текст, сохраняя обещания автора».

**Граница проверки:** template-прогон50/217,9с/110 черновиков ранее сверен по JSON/CSV. Новые11,3с и28,2% взяты из предоставленной PDF; исходный JSON LLM-прогона не приложен и независимо не пересчитан. Старый сценарий для10 слайдов теперь заменён короткими репликами по14 слайдам.
