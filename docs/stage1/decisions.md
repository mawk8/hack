# Решения этапа 1

14 ноября 2026. Это решения команды по подготовке проверки, не дополнительные требования организаторов.

| Решение | Основание и ограничение |
|---|---|
| Рабочая ветка `stage1` внутри существующего проекта | Не создаём дополнительную рабочую папку за пределами разрешённой области. Одновременных авторов одних файлов нет. |
| Короткие задания агентам из отдельных разделов ТЗ | Исполнитель и независимый проверяющий получают один контракт без истории разговора. Автоматический extractor навыка не поддерживает русские заголовки; разделы извлечены отдельно. |
| Служебные материалы сохраняем | Пользователь запретил удаление без отдельного согласования; очистка временных файлов и журнала навыка не выполняется. |
| Коммиты и отправку выполняет ведущий | Перед отправкой проверяется список файлов. Исходные объявления, локальные выборки и манифесты остаются вне Git. |
| PyArrow установлен только в `.tools/python` | Пользователь отдельно разрешил зависимость для реального чтения Parquet. Anaconda не менялась. |
| Из обучения baseline исключаются группы development и control | Проверяющий обнаружил, что старый флаг исключал только контроль. Новый фильтр исключает 363 строки вместо 229; остаётся 9 637. Development можно использовать для настройки, контроль — только для итоговой оценки. |
| Первоначальные файлы заморозки сохраняются побайтово | Новый фильтр обучения хранится отдельным дополнением с собственным хэшем. Старый `excluded_from_training` — устаревший индикатор только контрольных групп. |

Цена ошибок в процедурах — повторная подготовка/проверка; цена неполной группировки — завышенная оценка качества. Группировка близких текстов эвристическая: отсутствие всех смысловых дублей не доказано.

Подтверждено независимым аудитом: схема и агрегаты данных, пересечение train/public-test. Правильность автоматических меток не подтверждена. Ручная разметка и ответы организаторов остаются отдельными условиями принятия экспериментальных выводов.

## После стороннего отзыва и решения Astra, 14.11.2026

- Пользователь подтвердил **5/3/2**; вопрос о весах закрыт. Классификация = 5 × micro-F1, работоспособность до 3, черновики до 2. Генерация входит в первый полный прототип.
- Сохраняем один LLM-вызов: логически сначала услуги, категории и контекстные основания, затем тексты. Модель видит полный исходник; основания сохраняют субъект, отрицания и ограничения. Второй вызов не является независимой проверкой автоматически и требует измеренного выигрыша на development в полном сценарии.
- Не вводим фильтр по соседнему «не», некалиброванный confidence 0.6, настройку по control и обещание, что цитаты исключают выдумки. Дешевизна/превосходство локальной модели и цены из отзыва не подтверждены.
- Обычное перечисление собственных услуг не требует буквального разрешения отдельного заказа; в черновике такое разрешение не придумываем. Для явного «только внутри ремонта, отдельно не делаем» предлагаем временное консервативное исключение, пока организаторы не уточнят метки. Это гипотеза политики с риском потери recall. Два синтетических `organizer_pending` остаются с неизвестным эталоном, их не превращаем в gold.
- Title не используем по текущему контракту. Вопрос о категории для live-генерации сохраняем: архив прямо описывает выбор организаторов, PDF формулирует иначе.
- Переходим к разметке и первому прототипу вместо нового круга общего проектирования. Разметку и разработку можно вести параллельно; подтверждённые выводы H3 требуют human_verified эталона. Существующие 17 тестов используем повторно. На демо показываем известную ошибку при её наличии либо ограничение, не выдумывая ошибку или пользовательский эффект.

Полный независимый разбор: [Astra](third_opinion_astra.md). Платные запуски и само приложение этим разбором не выполнялись.
